Two deployments, deliberately separate:

  {{ include "bjw-s.common.lib.chart.names.fullname" . }}          waker, hostNetwork, :{{ .Values.service.main.ports.http.port }}    (Traefik fallback)
  {{ include "bjw-s.common.lib.chart.names.fullname" . }}-tunnel   ssh tunnel, pod network, :{{ .Values.service.tunnel.ports.tunnel.port }}  (Traefik primary)

The waker needs the node's network namespace to broadcast a magic packet, which
publishes its port on every node interface. The tunnel is unrestricted access to
Collie, so it stays in an ordinary pod where only its Service can reach it.

{{- if not .Values.ssh.existingSecret }}

NOTE: You have not set ssh.existingSecret. The tunnel cannot reach the dev box,
so the Traefik primary will never come up. Create the Secret and enable the
ssh-key volume:

  ssh-keygen -t ed25519 -N '' -f ~/.ssh/collie-waker
  ssh-keyscan -H {{ required "ssh.host is required" .Values.ssh.host }} > known_hosts

  kubectl create secret generic collie-waker-ssh-key \
    --namespace {{ .Release.Namespace }} \
    --from-file=ssh-privatekey=~/.ssh/collie-waker \
    --from-file=known_hosts=known_hosts

Append the public key to ~{{ .Values.ssh.user }}/.ssh/authorized_keys on the dev
box, then enable the volume and upgrade:

  helm upgrade {{ .Release.Name }} ./charts/collie-waker \
    --reuse-values \
    --set ssh.existingSecret=collie-waker-ssh-key \
    --set persistence.ssh-key.enabled=true

{{- end }}
